# OctoAcme Project Management Documentation

Welcome to the OctoAcme Project Management Docs. This folder contains comprehensive guides for running projects using the OctoAcme methodology.

## Quick Overview

OctoAcme is a project management approach built on principles of **customer-first delivery**, **iterative development**, **clear ownership**, and **data-informed decisions**. All cross-functional projects follow this lifecycle:

1. **Initiation** → 2. **Planning** → 3. **Execution** → 4. **Release** → 5. **Retrospective & Continuous Improvement**

### Core Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has a named Project Manager (PM) and Product Lead
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

### Key Roles

- **Project Manager (PM)**: Coordinates delivery, schedules, risk, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs and approvals

## How to Use These Docs

- **Starting a new project?** Begin with [Initiation](octoacme-project-initiation.md)
  - Define the problem, align stakeholders, and create a lightweight plan
  - Deliverables: One-pager, stakeholder list, high-level timeline, initial risks

- **Need to plan a project?** Go to [Planning](octoacme-project-planning.md)
  - Break work into shippable increments and identify dependencies
  - Deliverables: Prioritized backlog, estimates, release plan, Definition of Done

- **Currently executing?** Reference [Execution & Tracking](octoacme-execution-and-tracking.md)
  - Manage day-to-day delivery, standups, and quality standards
  - Focus: Team rhythm, PR workflow, testing, blocker escalation

- **Preparing to release?** Review [Release & Deployment](octoacme-release-and-deployment.md)
  - Pre-release requirements, deployment checklists, and rollback procedures
  - Includes: Release notes template, smoke tests, incident playbook

- **Finished a phase or project?** See [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)
  - Capture learnings and convert them into actionable improvements
  - Includes: Retro structure, action item template, continuous improvement tracking

- **Managing cross-functional risks?** Check [Risk Management & Communication](octoacme-risks-and-communication.md)
  - Maintain risk register, identify dependencies, and communicate with stakeholders
  - Includes: Risk lifecycle, escalation paths, communication templates

## Getting Started

### For New Team Members

1. Start with the [Project Management Overview](octoacme-project-management-overview.md) to understand the big picture
2. Review [Roles and Personas](octoacme-roles-and-personas.md) to understand team structure
3. Read the phase-specific docs as you encounter them in your project

### For Project Managers

1. Use the [Initiation Guide](octoacme-project-initiation.md) to kick off new projects
2. Follow the [Planning Guide](octoacme-project-planning.md) to structure work
3. Reference [Execution & Tracking](octoacme-execution-and-tracking.md) for day-to-day management
4. Use [Risk Management & Communication](octoacme-risks-and-communication.md) throughout the project
5. Facilitate retrospectives using [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)

### For Product Managers

1. Collaborate with PMs on [Initiation](octoacme-project-initiation.md) to define success metrics
2. Lead backlog prioritization and acceptance criteria in [Planning](octoacme-project-planning.md)
3. Align on metrics and outcomes in [Execution & Tracking](octoacme-execution-and-tracking.md)
4. Measure impact and plan follow-up work based on [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)

### For Developers

1. Understand the process in [Project Management Overview](octoacme-project-management-overview.md)
2. Review [Execution & Tracking](octoacme-execution-and-tracking.md) for PR workflow and quality standards
3. Contribute to retrospectives using [Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)

## Key Artifacts and Templates

Throughout these docs, you'll find templates and checklists for:

- **Project One-pager** — Problem, goal, success metrics, stakeholders, timeline, risks
- **Backlog Item Template** — Title, description, acceptance criteria, priority, estimate, owner
- **Risk Register** — ID, description, impact, probability, owner, mitigation
- **Weekly Status Template** — Progress, next steps, risks & blockers, decisions needed
- **Retrospective Format** — What went well, what could improve, action items

## Communication & Decision-Making

OctoAcme emphasizes transparent, timely communication:

- **Weekly sync** between PM + PdM
- **Twice-weekly standups** for delivery team (or as agreed)
- **Monthly stakeholder updates**
- **Ad-hoc escalations** as needed

For details on stakeholder communication and escalation paths, see [Risk Management & Communication](octoacme-risks-and-communication.md).
